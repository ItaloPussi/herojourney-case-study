Engineering a Personal Operating System.

Herojourney is a domain-driven system for turning long-term intentions into daily action and recorded evidence — while preserving the difference between plans, commitments, outcomes and historical truth.

ArchitectureModular monolith

Explicit module ownership and narrow integration seams.

BackendBun + Elysia

Prisma, SQLite, Better Auth and typed contracts.

FrontendReact + Vite

Feature-oriented UI with TanStack Query.

OperationsCI/CD + rollback

Immutable images, verified backups and health gates.

01 · THE PROBLEM

Most productivity tools flatten meaning.

A task, a commitment to a date, evidence that something happened, and a retrospective conclusion are not the same thing. Herojourney models these concepts separately so changing today's plan does not silently rewrite what yesterday meant.

Preserve the semantic difference between intention, commitment, evidence, outcome and memory.
02 · PRODUCT

A real product, not an architecture exercise.

The domain model is exercised through daily workflows: plan, commit, record evidence, review what happened and decide what changes next.

03 · ARCHITECTURE

Boundaries first. Frameworks second.

04 · ENGINEERING DECISIONS

Trade-offs are part of the product.

01

Modular monolith

Local reasoning and independent module evolution without premature distributed-systems overhead.

02

Events ≠ reads

Typed events represent facts that happened; Dynamic Context providers answer current-state questions.

03

Historical truth

Snapshots and explicit lifecycle boundaries prevent today's edits from silently changing yesterday's meaning.

04

Versioned exports

Immutable analytical schemas, deterministic ordering and pseudonymous references instead of raw IDs.

05

Single-node by design

Docker Compose + SQLite + verified backups keep self-hosting deliberately small and recoverable.

06

AI with guardrails

Coding agents operate inside architecture checks, ADR lifecycle rules, maintainability limits and CI gates.

05 · SECURITY ENGINEERING

Security is implemented in the edges.

SSRF-aware ingestion

HTTPS-only URLs, credential rejection, DNS checks, private-address blocking, redirect constraints and bounded response bodies.

Privacy-aware export

Persistence IDs stay private; stable HMAC-derived references and schema validation protect analytical exports.

Authentication boundary

Application profile identity remains separate from authentication identity and domain ownership.

Rollback-oriented deploys

Verified backups, digest-pinned images, migration checks, health verification and explicit restoration behavior.

06 · STACK

A pragmatic stack for a small operational footprint.
